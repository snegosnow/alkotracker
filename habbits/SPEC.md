# habbits — техническая спецификация

## Архитектура

- Next.js App Router и TypeScript в Node.js runtime. Серверные компоненты читают данные через серверный слой доступа. Серверные действия обрабатывают изменения журнала. Клиентские компоненты отвечают за формы и интерактивность графиков. Перед реализацией сверить соглашения с установленной версией Next.js и руководствами в `node_modules/next/dist/docs/`.
- Turso хранит таблицы приложения и авторизации. Drizzle ORM подключается через `@libsql/client`. SQL-миграции хранятся в репозитории и применяются отдельно от запуска приложения. Использовать отдельные базы для разработки, интеграционных проверок и продакшна. [Подключение Drizzle к Turso](https://orm.drizzle.team/docs/get-started/turso-new)
- Better Auth обслуживает регистрацию и серверные сессии через SQLite-адаптер Drizzle. Обработчик App Router расположен в `/api/auth/[...all]`. Настроить HTTPS, доверенный origin, лимиты запросов к входу, регистрации и сбросу пароля с общим хранилищем для всех экземпляров приложения. Сброс пароля использует одноразовые ссылки с ограниченным сроком действия и одинаковый ответ для зарегистрированных и незарегистрированных адресов. [Интеграция Next.js](https://better-auth.com/docs/integrations/next) · [Адаптер Drizzle](https://better-auth.com/docs/adapters/drizzle)
- Каждый серверный вход в приватные данные проверяет сессию. ID владельца берётся из сессии. Запросы чтения, записи и агрегации ограничиваются владельцем. Приватные результаты исключаются из общего кэша. Секреты `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`, `BETTER_AUTH_SECRET` и параметры отправителя почты доступны только серверу.

## Маршруты

| Маршрут | Доступ и назначение |
| --- | --- |
| `/` | Публичная точка входа с переходом к статистике и аккаунту |
| `/statistics` | Общедоступные ряды по странам, диапазонам и периодичности. Фильтры хранятся в URL. |
| `/login`, `/register`, `/forgot-password`, `/reset-password` | Публичные экраны аккаунта |
| `/dashboard` | Закрытая сводка. Состав и экран после входа определяются в design.md. |
| `/purchases` | Закрытый журнал, фильтры, итоги и операции с записями |
| `/api/auth/[...all]` | Обработчик Better Auth |

## Модель данных

| Таблица | Поля и ограничения |
| --- | --- |
| Таблицы Better Auth | Схема пользователей, учётных записей, сессий и проверочных токенов генерируется из конфигурации Better Auth. |
| `profiles` | `user_id` как PK и FK, `currency`, `currency_locked_at`, `time_zone` в формате IANA. |
| `purchases` | `id`, `user_id`, `category` со значениями `alcohol` или `tobacco`, `product_name`, `quantity_scaled`, `unit`, `total_minor`, `purchased_on`, `note`, `created_at`, `updated_at`. Индексы по владельцу и дате, а также по владельцу, категории и дате. |
| `stat_series` | `id`, `dataset_key`, `geography_code`, `metric_code`, `unit`, `frequency`, `source_name`, `source_url`, `methodology_url`, `release_id`, `published_on`, `imported_at`. Уникальный ключ набора, территории, показателя, периодичности и релиза. |
| `stat_observations` | `series_id` как FK, `period_start`, `value_decimal`. Уникальная пара ряда и начала периода. |

## Правила журнала

- Одна запись соответствует одной товарной позиции. Дата — календарный день `YYYY-MM-DD`. По умолчанию подставляется текущая дата в часовом поясе аккаунта. Отчёт включает начало выбранного периода и исключает начало следующего.
- Сервер проверяет категорию, реальность даты, длину названия и заметки, положительное количество и стоимость. Единицы MVP — штуки, упаковки, литры и миллилитры. Для табачной категории доступны штуки и упаковки. Штуки, упаковки и миллилитры принимают целые значения, литры — до трёх знаков после запятой. Количество хранится в тысячных долях указанной единицы.
- Стоимость хранится целым числом в минимальных единицах валюты. Сервер отклоняет неподдерживаемую точность и контролирует диапазоны суммы и итогов. Валюта фиксируется атомарно с созданием первой покупки и остаётся фиксированной после удаления записей. Разнородные единицы количества отображаются отдельно.
- История сортируется по дате покупки и ID с пагинацией. После сохранения или удаления обновляются журнал и сводка. Повторная отправка одного запроса создания использует тот же ID записи, чтобы исключить дубль.

## Импорт и отображение статистики

### Проверка источника от 24.11.2026

Официальная CSV-выгрузка ВОЗ успешно загружена и разобрана. Для Узбекистана найдены 23 наблюдения за каждый год с 2000 по 2022. Фильтр импорта — `DIM_GEO_CODE_M49=860`, `DIM_GEO_CODE_TYPE=COUNTRY`, `DIM_SEX=TOTAL`, `DIM_TIME_TYPE=YEAR`, `DIM_PUBLISH_STATE_CODE=PUBLISHED`, `IND_CODE=SA_0000001688`. Год берётся из `DIM_TIME`, значение — из `RATE_PER_CAPITA_N`. Поля `RATE_PER_CAPITA_NL` и `RATE_PER_CAPITA_NU` содержат границы оценки. Значения следует разбирать как десятичные числа. [Проверенная CSV-выгрузка](https://srhdpeuwpubsa.blob.core.windows.net/whdh/DATADOT/INDICATOR/EE6F72A_ALL_LATEST.csv)

Контрольное значение за 2022 год — 2.062959639 литра чистого алкоголя на человека возраста 15+. Отображение допускает округление до 2,06, хранение сохраняет исходную точность. Дата обновления показателя на странице ВОЗ — 13.05.2025. Лицензия указана как CC BY 4.0 с дополнительными условиями ВОЗ. В интерфейсе сохраняется атрибуция и ссылка на показатель. [Метаданные и условия использования](https://data.who.int/indicators/i/EF38E6A/EE6F72A)

Адрес выгрузки содержит LATEST, поэтому при импорте нужно фиксировать дату получения и хеш содержимого как идентификатор снимка. Это позволит различать обновления по одному адресу.

Поиск в SIAT и национальной базе ЦУР обнаружил годовой показатель 3.5.2. Помесячный ряд потребления пока не подтверждён. Перед использованием национального ряда требуется сверить его методологию с выбранным рядом ВОЗ. Решение по месячному экрану запрошено у пользователя. [Национальная база ЦУР](https://ns1.stat.uz/uz/goal/6)

### Порядок импорта

1. Серверная команда импорта получает зафиксированный релиз из доверенного источника. Проверяет метаданные, соответствие единиц и периодичности, даты, дубли и неотрицательные значения.
2. Импорт записывает проверенный релиз и наблюдения атомарно. Повторная загрузка того же релиза идемпотентна. Для каждой страны, показателя и периодичности интерфейс использует последний опубликованный успешно загруженный релиз выбранного набора.
3. Для годовых рядов начало периода — 1 января, для месячных — первое число месяца. В график и таблицу передаются только значения выбранного ряда. Пропуски маркируются отдельно и годовые значения не распределяются по месяцам.
4. Месячный набор допускается к выпуску после проверки методологии, территории, единиц, покрытия и условий использования. Формат импорта и поведение интерфейса можно проверить на тестовых данных до подключения реального источника.
